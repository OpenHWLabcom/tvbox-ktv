# 关键坑与经验（做这台 KTV 盒子踩过的坑）

供二次开发/移植参考。实机：B860AV1.1-T2（ZX296716 / Android 4.4.2 API19 / armv7）。

## 安卓侧

1. **Android 4.4 没有 `pm set-home-activity`** → 让新 App 成为默认桌面的办法是**卸载旧桌面**。旧桌面 apk 先备份。
2. **WebView = 老 Chromium**：本项目 UI 用**原生控件**（不用 WebView）；粒子/歌词自绘。
3. **焦点系统不可靠**：避免 `EditText` 抢焦点 → 采用**自绘区域导航 + `dispatchKeyEvent`**，不依赖系统焦点。
4. **改"区域/状态枚举"要全局搜替换**：本项目曾把导航从 2 区域改成 4 区域（0顶栏/1快捷按钮/2列表/3已点），但**漏改了列表点击回调里的区域号** → 鼠标点歌变成去点"快捷按钮"，**点歌失效**。教训：这类共享编号改动，**含点击回调全搜一遍**。
5. **`uiautomator dump` 在页面有动画时会失败**（窗口不 idle）→ 验证改用 `screencap` + 像素统计，或 `Log.d` 看 logcat。
6. **`input tap` / `input text` 在本 ROM 有效**（可脚本化测试点击/输入）。
7. **音量是逐设备的**：`dumpsys audio` 里 STREAM_MUSIC 形如 `40000000:11`＝`设备:音量`（0x2=SPEAKER, 0x4/0x8=耳机, 0x40000000=HDMI）。`settings get system volume_music` **不一定反映**当前输出设备音量——判断"没声音"要看 `dumpsys audio`。App 里加了音量保底（≤2 自动调到约 2/3）。

## 子系统(chroot)侧

8. ⚠️ **PATH 坑（很重要）**：开机由 `start-stop-daemon` 拉起脚本时 **PATH 不含 `/usr/bin`** → 脚本里必须用**绝对路径** `/usr/bin/python3`，否则 `nohup: can't execute 'python3'` **静默失败**（表现为"服务没起但日志不报错"）。
9. `start-stop-daemon --exec` **必须是 `/bin/sh`** 才能跑 `.sh`（写成 `--exec python3` 会变成用 python 跑 shell 脚本 → 失败）。
10. **守护用"端口探测"而不是 `pgrep`**（PATH 里可能没有 pgrep）。
11. 开机时旧 pidfile 可能造成 `start-stop-daemon` 误判"已在运行" → 开机脚本里先 `rm -f /run/<svc>.pid`。

## 曲库 / 存储

12. **U 盘挂载点**：本 ROM vold 把 U 盘挂到 `/storage/sda|sdb|sdc`；子系统里读挂载表用 **`/proc/mounts`** 最稳（本项目就这么做），比 `Environment.getExternalStorageDirectory` 靠谱。
13. **同一文件多路径**：`/sdcard`、`/storage/emulated/0`、`/mnt/sdcard` 可能是同一处的不同路径 → 列表会重复。本项目视频去重按 **文件名+大小**。

## 网络

14. 网易云 `https://music.163.com/song/media/outer/url?id=<id>.mp3`：**部分歌曲**(VIP/版权)会 302 到 404 → 后端**并发 HEAD 探测可播性**，只返回可播的。
15. 老安卓直连网易云 HTTPS 易踩 TLS 坑 → 让 App 走**盒子本地代理**（`127.0.0.1:8089`），TLS 由子系统的现代 Python 负责。
